# Agent Note: GME 工作流插件

Status: implemented

[English](2026-09-12-gme-workflow-plugin.md) | 中文

## 问题

用户需要在 Harness 中操作 GME Test Agent，同时保留 Codex 生成测试和修复代码，并明确不使用 tool-gme。重写 Git 子模块处理、失败分类、内存审计和 PR 选择会重复已有 Python 业务逻辑。

## 决策

可选 bundle 通过带身份验证的本机 HTTP API 注册四个工作流工具。后端负责任务、worktree 和验证证据，Harness 负责对话并记录工具结果。插件复用通过身份验证的已有后端，也可以通过 subprocess 服务启动自己的 Python 子进程并在卸载时终止它。模型参数不能改变后端路径或任务工作目录。

查询与修改请求具有不同的完成含义。修改返回已接收的任务，绝不自动重发。报告采用有长度限制的文本分页，并保留稳定任务标识。接口选择与自由提示词互斥，因为后端同时收到两者时会覆盖提示词。

## 考虑过的替代方案

复用 tool-gme 不符合用户要求。将 Python 编排逻辑移植到 TypeScript 会重复已有工作流。后端内部用 Harness 替换 Codex 留待后续实现，以便这一版独立验证插件接口。

## 验证

19 项针对性测试、插件类型检查与构建、局部 lint、无密钥会话回放，以及构建产物对真实后端的健康状态、目录和任务查询均已通过。本机 Web 配置已解析到链接的插件并持久保存后端配置。尚未执行真实 Codex 生成、GME 编译或 PR 提交。全仓导出 JSDoc 检查报告 Windows ACL 包中的 7 项既有问题，均在本次修改范围之外。

针对性测试覆盖 HTTP 契约、输入校验、报告分页、取消、错误传播、Python 启动、进程清理与异常退出后的重新启动。Loader 组合测试验证导出方式和真实工具调用。只读集成检查不得创建 GME 任务或 PR。

## 影响

运行时仍依赖 Python 和 Codex。关闭拥有后端的 Harness 进程可能中断任务；独立管理的后端不受插件卸载影响。当前不提供任务取消、任务自动恢复或专门仪表盘。替换 Codex 为 Harness 属于后续独立修改。
